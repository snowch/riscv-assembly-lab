# Shared course style in RISC-V Assembly Lab

Follow the [shared course design guide](https://github.com/snowch/cuda-python-lab/blob/main/docs/course-design-guide.md). The course retains its actual RV64GC/xv6 execution, computed observations, prediction gates, exercises, projects and saved-work keys.

The header keeps Calculator and Reference, adds Code runner and App status, and keeps the existing light/dark/system preference. Source moves to the footer. The lesson row combines Course lessons, completion and breadcrumbs. Its optional outline opens inline, uses plain module headings and direct lesson links, and closes with Escape while returning focus to the toggle. A modal takes Escape first.

Use local IBM Plex Sans and Mono, semantic light/dark surfaces, readable code and official Material Symbols Rounded. The source editor has a consistent dark surface; computed figures follow the page theme so their before/after and observed-state distinctions remain visible. Keep the real workbench controls, responsive split view, contained scrolling, editor sizing and fullscreen interactions.

The homepage keeps its existing original image beside the introduction on wide screens. On narrow screens, Start and the course choices precede the image. Essential prerequisites remain visible.

Keep optional source inspection, technical tools and references optional; preserve Calculator and Reference at every width. Labels remain visible with enough room for their icons and text rather than retaining the old 44-pixel icon-only width. This was a real phone overflow found after an offline save, not a reason to hide the labels again.

Functional tests cover learner actions, actual execution, restored results, both themes, keyboard interactions and phone/tablet/desktop widths. They do not establish learning effectiveness or physical Android performance.
