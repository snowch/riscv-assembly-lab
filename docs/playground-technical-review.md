# Independent playground technical review

Copyright © 2026 Christopher Snow.

Reviewed the standalone playground and shared-component changes under `docs/course-authoring.md`, the imported Assembly Lab contributor/style rules and `docs/playground-brief.md`. This reviewer did not write product code or draft the interface text. Browser checks used a separate local server on port 4252 and Chromium through Playwright. The managing task owns the complete CI, unit, browser and native-corpus checks; this report does not claim those results. All seven findings below were corrected and independently rechecked; no unresolved technical findings remain within this checked scope.

## Findings and corrections

1. **High: switching projects could overwrite another tab's newer source.** Two tabs had the same project open. Tab B saved `li t2,99`; tab A retained an untouched older source and selected another project. `store.select` refreshed the inactive stored project before `loadProject` saved the old editor again, so the newer source was overwritten without a conflict copy. **Corrected and independently verified:** the standalone controller no longer performs the redundant post-selection save, and the shell flushes source before changing the active project. Actual two-tab tests confirmed that the newer source survives project selection, opening an example and creating a project. Independent store probes also confirmed that simultaneous actual edits retain an other-tab copy, and a stale-tab delete retains the newer remote source while Undo restores the original.
2. **Medium: importing a C project changed its highlighted register.** A valid exported project with `result: "t0"` imported with `a0` selected because the import handler applied the C default to JSON too. **Corrected and independently verified:** JSON preserves its chosen result. A project with highlighted t0, stack observation, two data bytes and a0/a1 values 13/4 retained those settings and actually returned 17.
3. **Medium: floating project menus could overlap and intercept an action.** After opening Project actions and importing a project, opening Examples left both menus open. The Project actions “Save a copy” button intercepted a pointer click aimed at “Open example”. **Corrected and independently verified:** pointer dismissal, action completion and native toggle handling enforce one open menu. Keyboard verification used Enter on Project actions, Shift+Tab to Examples and Enter; Examples opened and Project actions closed. The selected example then opened without an intercepted pointer.
4. **Low: full-program helper text and memory-watch labels implied supplied scaffolding or a nonexistent symbol.** Complete assembly projects initially retained “The lab supplies entry, reporting and exit code”, and Hello World's memory-base option was labelled `lesson_data` although that source defines no such symbol. **Corrected and independently verified:** entry/resource help distinguishes complete source from supplied scaffolding; a build with no data symbol labels the fallback “Program memory base”. Its memory explanation names the actual ELF-region fallback. Last paused observations are explicitly distinguished from an exit state across inspector views.
5. **Low: a newly loaded project inherited the previous project's After memory selection.** Clearing the old observation left a fresh project showing unknown After bytes instead of its supplied Before bytes. **Corrected and independently verified:** project load resets the selection to Before. After a full-program run, opening the canonical array example immediately showed its supplied first byte and an active Before control.
6. **Medium: middle-clicking a lesson handoff opened the default project.** Preparing the transfer only in a primary `click` handler left the anchor's ordinary href unchanged for a middle click. In a real browser tab, source `li t2,123` opened a bare `/playground/` with the default addition. This was observed through the browser-context page event; middle-created tabs did not emit the source page's popup event in this runner. **Corrected and independently verified:** a shared handoff helper keeps the real href current and refreshes it for pointer, focus and context gestures. Actual middle-created tabs received the edited addition and Hello World source; the prepared exercise href also retained its selected inputs and activity.

7. **Medium: stepping a complete program’s valid exit produced a false error.** The minimal program loaded a0=0, a7=2 and executed `ecall`. Its first two steps paused correctly; the third reported “Execution left the user program before reaching another instruction”. The serial log contained a partial normal shell completion token, not a trap: the single bounded kernel-return chunk ended before UART output was fully drained. Running or Continue completed the same program. **Corrected and independently verified:** an asynchronous, bounded system-call step phase waits for user-text return or shell completion. The minimal program now finishes on its third step. A separate write(16) program returned to a user pause with a0=3 and text `Hi!`, then Continue completed exit(2). Kernel execution is not shown as a user-register observation.

## Browser and execution evidence

- Six combinations at 390, 800 and 1440 pixels in both actual light and dark themes: no assessment, completion or lesson-course controls in the standalone DOM, no document overflow and no page errors. Body colours were `rgb(245, 249, 248)` and `rgb(16, 30, 28)`. Real stepping and Continue produced the expected addition observation. Data contained 64 bytes and the real stack sample contained eight doublewords.
- Those combinations also checked native fullscreen round trips, retained paused PC/source, calculator shortcut isolation and cancelling an invalid New project form. Separate modal-fallback checks at 390 and 1440 pixels in dark theme retained the paused PC/source and returned focus; the desktop register layout stayed compact in the expanded workspace. The desktop separator responded to keyboard resizing without changing the machine. The current standalone class retains its layout when reparented into the fullscreen workspace.
- Full Hello World assembled and ran using the existing GNU/xv6 path. A direct run produced its text and left uncaptured register readings unknown. Start stepping produced actual registers and stack bytes; Continue with no selected breakpoint completed after the worker's full-program checkpoint guards changed. The remaining observation was labelled as the last pause, explicitly not an exit state. The explicit-exit stepping regression and a write-return-plus-exit regression passed after finding 7 was corrected.
- A TinyCC function implementing `a * 3 + b` with inputs 7/5 actually returned 26. Selecting its final real instruction address paused at the expected result; Continue captured the same result. A deliberately invalid C expression produced `main.c:2` and the diagnostic control selected the actual failing source line. No C source-to-instruction mapping was invented.
- Invalid starting setup preserved the paused VM, PC and source. Applying valid 64-bit register patterns cancelled the prior run, retained the exact patterns and used the next fresh machine. A custom assembly fragment produced its expected result.
- An exercise handoff transferred the edited code and the selected case's actual register values, then ran correctly in the new tab. The source lesson's draft stayed unchanged. The edited standalone Hello World source transferred as a complete assembly program and ran its changed message.
- Browser storage disabled, quota failure and corrupt workspace metadata each retained two usable tab projects across switching. The fallback message was visible and JSON export contained the edited source. Corrupt stored records were retained rather than overwritten. Malformed JSON and an invalid transfer fragment produced visible errors; a valid import preview could be cancelled without changing a paused machine. Script-like imported project names remained inert text.
- A GitHub-Pages-style `/riscv-assembly-lab/` subpath check passed the lesson handoff, relative asset/compiler/worker loading and actual execution of the edited fragment.
- The JSON/parser/store probe checked exact 64-bit values, duplicate aliases, reserved registers, unsupported versions, unsafe origin paths, byte bounds, fragment decoding, no-storage operation, per-project multi-tab additions, active edit conflicts and reversible deletion. It passed independently of the shell's tests.

## Probe corrections and limits

An early private script predated the move of Examples into a disclosure and timed out looking for its hidden selector. The corrected script opened the disclosure. A later pointer interception exposed the genuine concurrent-menu finding above. A subsequent copy assertion expected an older “not exit register values” phrase after the final copy changed to “They do not show the exit state”; the assertion was updated to check the same semantic qualification. These probe corrections are separate from the product findings and do not count as passing original commands.

This review is Chromium-based. It did not test physical mobile keyboards, assistive-technology speech, Safari or Firefox. It does not certify hardware timing, a general reverse debugger, or newly implemented instruction semantics. The changed path continues to use this repository's actual GNU/TinyCC builder, xv6 guest and debugger. The refactor and new app introduce no imported AArch64 Playground source or new vendored runtime in the inspected diff; this is a source-provenance observation, not a legal clearance.
