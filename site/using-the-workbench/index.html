Edit, run and compare

Registers are the processor’s working storage. Open the addition workbench. If a saved draft differs from the example below, choose Restore starter. Undo restore recovers your previous draft. The first two lines load values into registers. The third adds them into t2.

Predict t2, choose Build & Run and record t2 in Registers after the run finishes. In the editor, change li t0, 7 to li t0, 19. Predict t2 again, then choose Build & Run. How did increasing t0 change t2? Each run starts a fresh machine. Stop ends the current run.

A prediction is checked against the code you run, including your edits. A valid edit can produce a different result from the original example.

li t0, 7
li t1, 5
add t2, t0, t1

Choose what to inspect

The workbench shows the registers relevant to the example. Select Inspect registers for hexadecimal values, other decimal readings and individual bits. Open Tools to inspect memory, output, starting setup or saved projects.

Observations belong to the named pause or completed run. If you edit the code afterwards, build again before using the values to explain your changes.

Follow execution

Start stepping pauses before the first machine instruction of your code. Step instruction executes one machine instruction. In assembly, the execution highlight identifies the source line for the next instruction. A source line can expand into several machine instructions.

A breakpoint pauses before its instruction runs. In the addition example, choose the numbered button beside add and open Tools if it is closed. Choose Start debugging. Read t0, t1 and t2 at the pause. Can t2 hold the sum yet? Choose Continue and compare t2 after the program finishes.

C debugging uses actual instruction addresses because this compiler provides no C source-line mappings. In Tools → Program, choose Machine instructions to inspect the executable from the last successful build.

Try an optional exercise

After the experiment, open Optional exercise. Read the task and choose Load exercise. The editor opens your saved exercise draft, or the starter if none exists. The task stays visible above that editor. Build & Run tries the selected case. Choose Check all cases to run your current code on fresh inputs, and read the case results below the editor. Return to example brings back your example draft.

Use familiar editing controls

Syntax highlighting and bracket matching help you read the code. Diagnostics report whether the tools accept it.

Make room for code

Resize from the editor’s lower-right corner, or choose Expand editor. Full screen fills the screen; when fullscreen is unavailable, Expand workspace fills the browser window. Escape leaves fullscreen or the expanded workspace. Close Find first if it is open.

Keep or restore your work

The example and optional exercise keep separate drafts. Drafts save in this browser when storage is available; check the save message. Download code keeps a source file.

Restore starter and Load reference solution replace the active draft. Undo restore recovers the previous draft in that activity. In Tools → Program you can read the supplied entry, reporting and exit code.

A saved project keeps source and starting setup together. Export project saves both in one JSON file. Saved drafts and projects do not keep a running or paused machine.

Work on an independent project

Use the lesson’s example and optional exercise for guided work. To keep an independent experiment, open Tools → Projects and choose Save a copy. The project opens in the same editor with its own source and starting setup.

In a lesson draft, Apply setup opens a project copy with the values you entered. The lesson draft and its starting setup stay unchanged.

A copy of an exercise uses the selected case’s inputs and data. Project edits keep the lesson draft unchanged. Choose Return to lesson to restore the example or exercise you left.

Open the playground from the course overview to work on independent projects. In a lesson, use Tools → Projects to keep working in the same editor.
