Edit, run and compare

Registers are the processor’s working storage. Open the addition workbench. If a saved draft differs from the example below, choose Restore starter; Undo restore recovers your draft. This example’s first two lines load values into registers; the third adds them into t2.

Predict what t2 will hold, then choose Build & Run. Inspect Registers after the code finishes. Change a starting number in the editor, predict again, and run the edited code. Each run starts a fresh machine. Stop ends the current run.

li t0, 7
li t1, 5
add t2, t0, t1

Open the addition workbench

Choose what to inspect

The inspector sits beside the editor on a wide screen and below it on a phone. Select a named tab. The addition example has no Memory tab.

TabWhat it shows
RegistersValues captured at a pause or after your code completes.
MemoryData or stack bytes, in lessons that provide a memory view.
OutputYour program’s console text. This addition prints no console text.
DiagnosticsCompiler, assembler and linker messages, plus execution errors.
DebuggerBreakpoints and the register or memory values you choose to watch.

Follow execution

Start stepping pauses before the first machine instruction of your code. Step instruction executes one machine instruction. In assembly, the execution highlight identifies the source line for the next instruction. A source line can expand into several machine instructions.

A breakpoint pauses before its instruction runs. In the addition example, select the line number beside add, then choose Start debugging. Continue runs to the next selected breakpoint or the end of your code. C debugging uses actual instruction addresses because this compiler provides no C source-line mappings.

Try an optional exercise

After Change it and run again, open Optional exercise. Read the task, then choose Load exercise. The editor opens your saved exercise draft, or the starter if none exists. Check all cases runs your code on fresh inputs. Return to example brings back your example draft.

Use familiar editing controls

Syntax highlighting and bracket matching help you read the code. Diagnostics report whether the tools accept it.

KeysAction
Ctrl / ⌘ + FFind text.
Ctrl / ⌘ + ZUndo an edit.
Ctrl / ⌘ + EnterBuild and run.
TabIndent code.
Escape, then TabLeave the editor using the keyboard. Close Find first if it is open.

Make room for code

Resize from the editor’s lower-right corner, or choose Expand editor. Full screen fills the screen; when fullscreen is unavailable, Expand workspace fills the browser window. Escape leaves fullscreen or the expanded workspace. Close Find first if it is open.

Keep or restore your work

The example and optional exercise keep separate drafts. Drafts save in this browser when storage is available; check the save message. Download code keeps a file.

Restore starter replaces your edits; Undo restore recovers them. View complete program shows the supplied entry, reporting and exit code around your work.
