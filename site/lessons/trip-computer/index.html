Module 13 · Working programs in xv6

Build a checked trip calculation

Combine bounded records, status masks, a loop and a helper call in one executed program.

Loading lesson…

These observations belong to the source captured at the start of this run. Build again to use your edits.

A trip record here occupies four bytes. Its first two bytes hold an unsigned distance in little-endian order. Byte two holds status bits, and byte three is reserved. The byte view marks each record’s start. The count in t0 says how many records to inspect, with a maximum of four.

The mask in t1 chooses the status bit or bits that make a record active. A record contributes when its status AND the mask is nonzero. The scale in t2 multiplies the final total. The supplied values keep every distance, sum and scaled result within the unsigned 64-bit range.

The fragment first walks the records and accumulates distances in a0. It then passes the scale in a1 and calls a leaf helper, a function that calls no other function. The helper returns the scaled total in a0. The snapshot is taken after that helper returns and the caller jumps past its body.

Predict, then check

What scaled total is returned after only the first three records are considered?

      Inspect the register bits

      What the instructions do

      The count check precedes the read. For a zero count, the loop skips all record accesses and the zero total reaches the scaling helper. Otherwise the pointer advances by the full four-byte record size, not by the two-byte distance field or the one-byte status field.

      A status byte is a bit pattern. Comparing it with the mask for equality would reject a record that has the desired bit plus another bit. AND tests the requested bits while allowing unrelated status bits. The branch decides whether to include the distance; it does not change the stored record.

      The helper call separates accumulation from scaling. Its result contract is a0, so the caller uses that returned value rather than assuming an earlier temporary register still holds the answer. This program combines the mechanisms already taught, but one successful example is not enough evidence. Fresh cases include an empty list, different selected bits and a mask selecting nothing.

      Change it and run again

      Change the record count from three to four. Predict whether the extra record contributes under the current mask, then run again without changing the data.

      A hint

      First decide whether the fourth record is inspected; then test its status against the mask.

      Use it on fresh inputs

      Using at most four records from lesson_data, sum each unsigned 16-bit distance whose status byte has any bit selected by t1. t0 supplies the record count and t2 the scale. Return total * scale in a0. Do not read a record after the count is exhausted. The cases keep the product within range.

      Each case starts a fresh xv6 machine. The same submitted code must pass every case.

          Reference solution

          Compare the mechanism after you have tried the challenge. Your code can differ and still pass.

          la t3, lesson_data
li t4, 0
li a0, 0
scan_records:
    bgeu t4, t0, scale_records
    lbu t5, 2(t3)
    and t5, t5, t1
    beqz t5, next_record
    lhu t6, 0(t3)
    add a0, a0, t6
next_record:
    addi t3, t3, 4
    addi t4, t4, 1
    j scan_records
scale_records:
    mv a1, t2
    call scale_total
    j trip_done
scale_total:
    mul a0, a0, a1
    ret
trip_done:
