Scale before dividing

Calculate a consumption figure without discarding its fractional contribution or overflowing a narrow intermediate.

The trip computer records fuel in millilitres and distance in metres. To obtain whole millilitres per 100 metres, multiply fuel by 100 and divide that product by distance. Integer division discards any fractional part, so the order of these operations matters.

For this activity both inputs are unsigned 32-bit values already placed in 64-bit registers with their upper bits clear. Their product with the scale fits in 64 bits. A normal RV64 mul retains that complete intermediate; mulw would discard needed bits and sign-extend its 32-bit result.

The example uses a nonzero distance. The challenge adds an application rule: zero distance must return zero. That rule is chosen by this calculation; it is not the result that a RISC-V unsigned divide by zero supplies.

      Inspect the register bits

      What the instructions do

      A wide destination helps only when the arithmetic producing it keeps the needed bits. Multiplying with mulw and then using divu cannot recover the higher product bits lost by the earlier operation. Choose the multiplication width before the product is formed.

      Dividing fuel by distance first introduces a different loss. A small fuel count can produce a zero quotient even though the scaled calculation would return a nonzero whole number. Multiplying that already-truncated quotient afterwards does not restore the discarded fraction.

      The stated input bounds make the product safe here. For arbitrary unsigned 64-bit fuel, multiplication by the scale could itself wrap. Such a broader contract would need a range check or a multi-register calculation; changing the final division alone would not solve it. The challenge keeps the narrower, explicit input bounds.

      Change it and run again

      Load fuel 1 and distance 3. Compare multiply-then-divide with divide-then-multiply. Restore the former order, then try mulw with the original large fuel reading.

      A hint

      The first comparison loses a fraction too early; the second loses high product bits. They are different mistakes.

          Reference solution

          Compare the mechanism after you have tried the challenge. Your code can differ and still pass.

          beqz t1, zero_distance
li t3, 100
mul t2, t0, t3
divu t2, t2, t1
j consumption_done
zero_distance:
li t2, 0
consumption_done:

          Equivalent intent for this target. This assembly was written for teaching; it is not presented as compiler output.

          C intent

          unsigned long consumption(unsigned long fuel, unsigned long distance) {
    if (distance == 0) return 0;
    return fuel * 100UL / distance;
}
