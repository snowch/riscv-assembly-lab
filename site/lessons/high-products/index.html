Module 8 · Products and division

Read both halves of a product

Use the signed or unsigned high-product instruction when a low half is not enough.

These observations belong to the source captured at the start of this run. Build again to use your edits.

A full product of two 64-bit inputs can be split across two registers. The low half contains product bits 0 through 63. The high half contains bits 64 through 127. mul supplies the low half; a separate instruction supplies the high half.

mulh treats both factors as signed values. mulhu treats both as unsigned values. They can therefore produce different high halves for the same input bits. The editor applies both instructions to one pair of factors and also retains their common low half.

The li lines establish the inputs before either multiplication. Temporary registers t3 and t4 hold additional observations. Predict the unsigned value of t3 after the entire fragment runs; its instruction is mulhu.

    Inspect the register bits

    What the instructions do

    The high half records information that the low-half instruction discards. You cannot reconstruct that information by sign-extending the low result: different full products can share the same low pattern.

    Keep both original factors until both instructions have read them. Using a source register as the destination of the first multiplication would change an input to the second. The challenge puts the two halves in distinct destinations, so neither factor is overwritten.

    RISC-V also has mulhsu for a signed first factor and an unsigned second factor. The order of those roles matters. Choose from the required interpretation of each factor, rather than from whether a register happens to display a minus sign. The result cards also show hexadecimal patterns so the bits remain visible.

    Change it and run again

    Set both inputs to -1. Compare mulh with mulhu, then change mulhu to mulhsu and run again. Keep the common mul result.

    A hint

    The same all-ones input represents a negative signed value or a large unsigned value. Changing only the high-product instruction changes which mathematical product is represented.

    Use it on fresh inputs

    t0 and t1 arrive as unsigned 64-bit factors. Put the low 64 bits of their full product in t2 and the high 64 bits in t3. Preserve both inputs. The two result registers together must retain all 128 product bits.

    Each case starts a fresh xv6 machine. The same submitted code must pass every case.
