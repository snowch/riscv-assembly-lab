Follow the executable’s entry contract

Connect a source fragment, a callable function and the complete ELF user program.

An object file contains machine code and names that the linker still needs to resolve. The linker combines those contents, gives them addresses and writes an executable. This lab’s executable uses ELF, a file format whose headers describe the target, the entry address and the memory regions to load.

The program entry is where a newly started process begins. It is not an ordinary function called with a saved return address. The supplied _start code prepares the lesson’s inputs, runs your fragment, reports its results and asks xv6 to exit. Open View complete program to see that surrounding code.

Your fragment can still call an ordinary helper. The example calls advance and jumps past its body after the helper returns. ret returns from advance to its caller. It does not terminate the process. The register cards observe the state after the fragment reaches the supplied reporting code.

    Pinned registers

    Pin a register to keep its readings together. “Changed” compares the current observation with the preceding pause or captured result. Watches do not stop execution.

    Memory watches

    A memory watch reads bytes when the machine pauses. Choose a base address, a signed byte offset and a width. Bytes are read in little-endian order: the first byte holds the lowest eight bits of the value. New watches refresh at the current pause without executing an instruction.

      What the instructions do

      The source label _start and the executable’s entry field serve related but different jobs. The label names code during assembly and linking. The ELF header tells xv6 the resulting start address. A file loader uses the executable’s loading information, not the visual position of the first interesting line in the editor.

      xv6 is already running when it loads this user executable. It supplies the process’s address space and initial stack. This is not a firmware reset experiment, a board boot image or a direct write to a physical device. Those environments require their own startup and handoff contracts.

      Changing the editor does not change an executable that was already built or a process that already ran. Build & Run creates and launches a fresh image. The source-change notice keeps that distinction visible when the displayed register snapshot belongs to an earlier version. Returning the correct value still matters independently of assembling and loading successfully.

      Change it and run again

      Remove j entry_done immediately after call advance. Predict where ret sends control after the helper returns. Choose Start stepping and follow that return with Step instruction; use Stop to end the repeated path. Restore the jump afterwards.

      A hint

      The call’s return address is the instruction immediately after the call. Check which instruction occupies that address after removing the jump.
