Module 12 · C at the boundaries

Separate C overflow from machine wrapping

Run defined unsigned wrapping and protect a bounded increment before it wraps.

An unsigned C addition has a defined wrapping result. For unsigned long on this target, it keeps the low 64 bits. The starting function adds the two supplied unsigned arguments. Its behaviour at the end of the unsigned range follows the C type’s rule as well as the instructions that implement it.

Signed C addition has a different contract. If the mathematical signed result is outside the signed type’s range, C describes the operation as undefined behaviour: the language places no requirements on that execution. It does not promise a wrapped value, an exception or an error message.

A RISC-V add instruction still has defined low-bit behaviour. That fact does not require a compiler to translate an overflowing signed C expression into that instruction. An optimiser can use the assumption that a defined signed addition does not overflow. This page’s executed cases use defined C; they do not treat one compiler’s response to undefined behaviour as a portable answer.

      Inspect the register bits

      What the instructions do

      Interpret the result in the type used by the source calculation. A signed decimal display can show a negative reading for a perfectly valid unsigned result whose top bit is set. The hexadecimal bits identify the same stored value without choosing a signed reading. A display choice does not change the C arithmetic that produced those bits.

      If wrapping is unwanted, express a different application rule. A bounded increment can test whether the input is already the largest allowed value, then leave it unchanged. Testing first makes the rule explicit. Adding first and hoping a later comparison reconstructs an invalid signed operation does not repair undefined behaviour. In C, 0UL is zero of type unsigned long. The ~ operator complements every bit, so ~0UL is the largest unsigned long value.

      Tests and compiler warnings help find mistakes, but neither proves that all possible inputs are safe. A run-time checker also observes only paths that execute. The exercise’s boundary cases make the intended behaviour visible without asking the browser compiler to diagnose every kind of C error.

      Change it and run again

      Change the unsigned return calculation to a - b and use a = 0, b = 1 in a fresh call. Explain the hexadecimal result using unsigned arithmetic.

      A hint

      Subtraction has the same unsigned modulo rule; the signed decimal reading is a separate choice.
