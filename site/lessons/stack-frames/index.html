Module 9 · Functions and the stack

Keep values in a stack frame

Inspect an active frame and preserve a saved register while a helper changes its argument registers.

Loading lesson…

These observations belong to the source captured at the start of this run. Build again to use your edits.

A return address is not the only value a caller may need after a helper runs. Argument registers such as a1 are caller-saved: a callee is allowed to change them. Registers s0 through s11 are callee-preserved, so a function that changes one must restore its incoming value before returning.

The example first copies the starting sp into temporary register t0, then reserves a 64-byte frame. It saves s0 at offset zero, changes the working s0, and loads the saved value into t1. Subtracting the current pointer from the earlier pointer records the reservation size in t2.

This example deliberately stops with the frame still active. Its memory view begins at the final sp, so the first eight bytes belong to the saved 64-bit value. Little-endian order puts its lowest byte at the lowest address. The challenge completes a returning function instead, and must release its frame.

Predict, then check

What does t1 hold after it loads the saved frame value?

Changing the working register does not change the separate value already stored in memory.

    Inspect the register bits

    What the instructions do

    A saved value and the register currently used for a calculation are different storage locations. The load reads the frame bytes, so reusing s0 afterwards does not destroy the saved copy. The byte view connects the offset in sd and ld to the addressed storage.

    A callee-preserved register solves a different problem from a temporary register. A function may use s0 to keep a reserve across a call because its helper must preserve s0. That function still owes its own caller the incoming s0, so it saves the old value before reusing it.

    The challenge’s helper deliberately clears a1. Keep the reserve somewhere that survives the call, then restore the saved register and release the frame before returning. The final snapshot shows the restored state; it does not promise that popped frame bytes below sp remain visible in the inspection window.

    Change it and run again

    Change the value saved into the active frame and inspect its low-address bytes. Then load from offset 8 instead of offset 0 and compare the observation. Restore the correct offset afterwards.

    A hint

    Each 64-bit slot occupies eight bytes. Reserving a frame does not put the saved value into every slot.

    Use it on fresh inputs

    a0 holds an unsigned distance, a1 holds a reserve, and s0 holds a caller-owned value. Complete trip_report to return half the distance plus the original reserve in a0. The supplied helper clears a1. Keep its code unchanged. Preserve incoming s0 and sp, protect ra, and keep the 32-byte frame aligned.
