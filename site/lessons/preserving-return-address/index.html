Module 9 · Functions and the stack

Keep the return address across a call

Save a function’s incoming return address before it calls another helper.

Loading lesson…

These observations belong to the source captured at the start of this run. Build again to use your edits.

A function that calls another function needs two return destinations at different times. It first receives the address of its own caller in ra. Its nested call then replaces ra with an address inside the current function. Save the first address before making that call.

The stack is memory used by active calls. Its current boundary is the stack pointer, sp; reserving space subtracts from that pointer because this stack grows towards lower addresses. The space reserved by one invocation is its stack frame.

The standard calling convention requires 16-byte stack alignment throughout a procedure: sp stays a multiple of 16. This example reserves 16 bytes, uses sd ra, 8(sp) to save the 64-bit address eight bytes above the new pointer, and uses ld to restore it. Releasing the frame adds the same size back to sp.

Run the whole fragment and inspect the final a0 and sp. The snapshot is after both functions return, not a sequence of intermediate stack states. The lab supplies an aligned initial stack pointer and its reserved inspection area.

Instruction path

The program counter (PC) holds the address of the next machine instruction. Arrows record addresses observed during execution.

    Inspect the register bits

    What the instructions do

    The helper’s return and the report’s return need different addresses. Restoring the saved ra after the nested call lets the report’s final ret reach the original caller. The call instruction does not allocate a frame or preserve an older return address automatically.

    If the report returns through the nested call’s address, it can revisit its own post-call instructions rather than leave the function. The helper may have returned correctly even though its caller can no longer return correctly.

    Restoring sp releases the frame’s space. It does not erase the saved bytes. Released storage is no longer a place where that function may keep live values. The challenge checks the actual stack pointer against its captured initial value, rather than relying on a fixed numerical stack address.

    Change it and run again

    Temporarily remove the ra save and restore while keeping the nested call. Run the changed program, use Stop if it does not finish, and then restore the two instructions.

    A hint

    Identify which address the helper call leaves in ra. The final ret uses that address unless you restore the report’s incoming one.
