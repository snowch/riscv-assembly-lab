Starting setup

Set the values supplied before your code starts. Apply setup ends the current run; the next build starts a fresh machine.

Apply setup opens a project copy with these values. Your lesson draft and its starting setup stay unchanged.

Use one assignment per line, such as t0 = 7. Decimal is the default; use 0x for hexadecimal or 0b for binary. Values must fit 64 bits. The starting setup does not accept zero, sp, gp or tp. The supplied code prepares the stack pointer; zero always reads zero.

Use pairs of hexadecimal digits separated by spaces, such as 01 FF. Up to 64 bytes; remaining bytes start at zero.

A complete assembly program supplies its own initialisation and data. Set those values in the source.

Data shows 64 bytes from lesson_data. Stack shows 64 bytes from the observed stack pointer, sp. Marks a register in the inspector. It does not change execution.

    Pinned registers

    Pin a register to keep its readings together. “Changed” compares the current observation with the preceding pause or captured result. Watches do not stop execution.

    Memory watches

    A memory watch reads bytes when the machine pauses. Choose a base address, a signed byte offset and a width. Bytes are read in little-endian order: the first byte holds the lowest eight bits of the value. New watches refresh at the current pause without executing an instruction.

    Up to eight watches. Offsets range from −4096 to +4096 bytes.

      Own the inputs and exit
      The worked program stores two counts in its data section. _start loads them into a0 and a1, then calls combine.
      The label _start names the program’s entry. The .data section defines its count values; no Starting setup values are added.
      

      combine puts its result in a0. ret returns to the instruction after the call. The caller copies that value into s0 before using a0 for exit.
      

      The exit request puts zero in a0 and the xv6 exit number in a7. Its ecall enters xv6 to finish the process. This program has no supplied reporter.
      1. Open the worked program as a new project. Your existing project is kept.
      2. Select the line number beside the exit ecall to set a breakpoint. Open Tools if it is closed, then choose Start debugging.
      3. At that pause, read s0 in Registers and inspect the stored counts under Tools → Memory. Explain how each loaded count reached the helper and how the result reached s0.
      4. Choose Continue to let the exit call complete. The retained observations describe the last pause, not the exit state.
      Apply it to a different calculation
      The fresh project stores 31 and 17. In combine, replace add a0, a0, a1 with sub a0, a0, a1. The caller still copies the result into s0 before exit.
      Predict s0. Set a breakpoint on the exit ecall, open Tools and choose Start debugging. How does the paused s0 compare with your prediction?
      • Which source defines the starting counts, and which instructions load them?
      • Where does call transfer control, and where does ret return?
      • Why is the returned result copied before a0 is prepared for exit?
      • Which pause supports your claimed result, and what does that observation leave unknown about exit?
      Check your explanation against the source and paused machine. A matching number alone does not explain the input, call and exit boundaries.
      

      Using the playground
      Source and execution
      The editor and run controls work the same way in lessons and independent projects. Open Tools when you need more inspection, starting setup or saved projects. Close Tools to concentrate on the code and its relevant results.
      

      Program shows your current source inside its complete program. Expand a supplied section to inspect the setup, capture or reporting code. Your fragment stays editable in the editor.
      

      Machine instructions shows the executable from your last successful build. Build again after editing the source. During stepping, PC marks the next instruction to execute.
      

      Registers shows observations from execution. Pin useful registers, compare changed values, or choose All to see every integer register.
      Choose the source you want to write
      An assembly fragment is a group of instructions inside a supplied program. You can concentrate on those instructions; Tools → Program shows the entry, reporting and exit code around them.
      

      A C project defines a function named lesson, such as long lesson(long a, long b). The supplied caller passes a0 and a1 as its arguments and captures the return value in a0. Do not add main, system headers or library calls.
      

      A complete assembly program defines _start and includes its own exit code. Its registers and data come from its source and xv6, so the fragment’s starting-register and data controls do not apply.
      Run and inspect
      Build & Run assembles and links your source, then runs it as an xv6 user process. C projects first compile their function with TinyCC. Every new run starts a fresh machine.
      

      Start stepping pauses before your first machine instruction. Step instruction executes one machine instruction. A source line can expand into several machine instructions.
      

      A breakpoint pauses before its instruction runs. Choose the numbered button beside an assembly instruction, open Tools if it is closed, then choose Start debugging. Continue runs to a selected breakpoint or the end of your code. For C, select actual instruction addresses in Debugger; this compiler does not provide C source-line mappings.
      

      Register and memory readings belong to the observation named beside them. Assembly fragments and C functions capture a report after their code. Complete programs can exit without that report: a last paused observation is not an exit state.
      Supply starting values
      For fragments and C functions, Setup supplies register values before your source runs. Use assignments such as t0 = 7, one per line. Apply setup commits the entries and ends the current run. Editing the setup form alone does not change a paused machine.
      

      Data bytes fills the area named lesson_data. Hexadecimal uses digits 0–9 and A–F; two hexadecimal digits describe one byte. Unspecified bytes start at zero.
      

      Memory view chooses the 64-byte region shown in Memory. Data starts at lesson_data. Stack starts at the observed stack pointer, sp. The Stack tab and memory watches provide further observed readings.
      Keep your projects
      Source and setup save together in this browser when storage is available. Check the save message. A project saves your code and setup, not a running or paused machine.
      

      Open Tools → Projects to open a saved project, choose an example, import a file or create a new project. Open example and Import file create new projects and keep your other work. Save a copy keeps the current source and setup in another project.
      

      From a lesson, Save a copy opens an independent project in the same editor. The lesson draft stays available through Return to lesson. An exercise copy uses the selected case’s inputs and data.
      

      Export project saves the source and setup in one JSON file. Download code saves only the source. Import file accepts project JSON, assembly source (.s or .asm), or C source (.c). Check Import as before opening a source file.
      

      If storage is unavailable, you can keep working in this tab. Export project before leaving to keep that work. Delete project can be reversed with Undo delete.
      Know the execution environment
      Programs target 64-bit RISC-V and run in xv6. Its system calls differ from Linux and teaching simulators. In this guest, write is system call 16 and exit is system call 2.
      

      The playground supplies console output, but no console input. The guest does not provide floating-point process state. Stepping shows functional execution, not physical hardware timing.
